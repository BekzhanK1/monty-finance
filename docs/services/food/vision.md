# Видение и принципы

## Одна фраза

**Домашняя кухня как система:** планируем, готовим, покупаем — в одном месте, вместе.

## Проблема

- Меню «в голове» или в переписке — забывается, дублируется, не согласовано.
- Список покупок собирается вручную и не совпадает с тем, что реально готовите.
- Рецепты разбросаны (ссылки, заметки, скриншоты) — нет единого каталога «наших» блюд.
- Неясно, **что уже есть дома** и что докупить.

## Ценность (outcomes)

| Результат | Как измеряем успех |
|-----------|-------------------|
| Меньше «что на ужин?» | Неделя заполнена слотами меню ≥ 5 вечеров |
| Меньше лишних покупок | Список генерируется из меню, позиции отмечаются |
| Быстрее планирование | Повтор прошлой недели / шаблон ≤ 1 мин |
| Общая картина для пары | Оба видят одно меню и один список без синхронизации вручную |

## Не цели (на старте)

- Соцсеть рецептов, публичные профили, рейтинги от чужих пользователей.
- Доставка еды, заказ из ресторанов, трекинг калорий «как MyFitnessPal» (это Health).
- Сложный учёт склада как в ERP (точные остатки по SKU магазина).
- Мульти-дом / гости с отдельными правами.

## Принципы продукта

1. **Пара = один дом** — все данные общие; конфликты редки → на MVP достаточно last-write-wins.
2. **Сначала план, потом покупки** — меню первично; список — производная (плюс ручные позиции).
3. **Свободный текст допустим** — не обязаны структурировать каждый рецепт; но структура даёт автоматизацию.
4. **Мобильный first** — Telegram Mini App, большие зоны нажатия, недельный вид.
5. **Русский быт** — названия продуктов, единицы (г, мл, шт, ст.л.), привычные приёмы пищи.
6. **Постепенная глубина** — можно жить только с «название блюда + неделя»; ингредиенты и кладовая подключаются позже.
7. **Честная интеграция с Finance** — деньги не выдумываем; цены в списке опциональны, транзакция — явное действие.

## Позиционирование в superapp Monty

Food — **вертикаль «дом»** рядом с Finance. Общее:

- один вход (Telegram / JWT),
- shell «Все сервисы»,
- в перспективе — общий `household` / workspace.

Food **не дублирует** бюджет целиком, а **подаёт события** (закрытый список покупок → черновик траты на продукты).

## Персоны (упрощённо)

| Персона | Потребность |
|---------|-------------|
| **Планировщик** | Раз в неделю раскладывает меню, генерирует список |
| **Готовящий** | Смотрит «что сегодня», открывает рецепт/гид |
| **Покупающий** | Идёт в магазин со списком, отмечает купленное |

Один человек может совмещать все роли; важно, что второй в любой момент видит то же самое.

## Эмоциональный тон UI

Спокойный, «домашний», без перегруза метриками. Акцент на **неделе и сегодня**, не на годовой аналитике (она — в Finance/Health позже).
