# Food 2.0 — кухня как система

Полная переработка Food (октябрь 2026): учёт продуктов, один живой список покупок, меню по дням, рецепты с проверкой «что есть дома». Интерфейс — на дизайн-системе Monty 2.0 (тема Telegram, `src/ui`).

## Навигация

Пять вкладок внизу (свой таб-бар внутри `/food`; «Назад» Telegram ведёт в «Ещё»):

| Вкладка | Маршрут | Что делает |
|---|---|---|
| **Сегодня** | `/food` | Меню на сегодня с готовностью и кнопкой «Приготовил», карточка списка покупок, «Скоро испортится», «Заканчивается» → в список одной кнопкой, подсказка спланировать завтра |
| **Меню** | `/food/menu` | Неделя, полоса дней, 4 приёма пищи на выбранный день. Шторка: поиск блюда (сначала подходящие приёму пищи, фильтр «Всё есть дома»), своё блюдо без рецепта, порции, «Приготовил», замена, удаление. «Купить продукты на неделю», «Повторить прошлую неделю» |
| **Покупки** | `/food/shopping` | Один живой список, сгруппированный по отделам магазина. Быстрый ввод с разбором («молоко 2 л», «2 кг картошки», «сыр 300г»), подсказки из справочника, «для: Плов» у позиций из меню. Тап — в корзину; «Завершить покупку» → в запасы + сумма чека в Finance; некупленное переезжает в новый список |
| **Запасы** | `/food/pantry` | По местам хранения (холодильник / морозилка / шкаф), ± с шагом по единице, статусы «Испортится через N дн.», «Просрочено», «Заканчивается», «Закончилось». Фильтр «⚠️ Внимание». Шторка: количество, место, срок (3 дня / неделя / месяц / дата), минимальный остаток, «В список покупок» |
| **Рецепты** | `/food/recipes` | Поиск по блюду или продукту, фильтр «Можно приготовить», карточка с пересчётом порций, отметками ✓/◐/○ по составу, шагами, «В меню», «Докупить» / «Приготовил». Редактор: продукты вводятся текстом, новые создаются сами |

## Решения (продолжение [decisions.md](./decisions.md))

| ID | Решение |
|----|---------|
| D14 | **Конвертация единиц**: кг↔г, л↔мл везде (готовность блюда, списание, вычитание из списка, пополнение запасов). Ложки/шт/уп не конвертируются — несовместимые единицы помечаются, а не угадываются. Заменяет D6 |
| D15 | **Один живой список** на дом. «Из меню» и «Заканчивается» **досыпают** в него, не создавая новый, и идемпотентны: учитывают запасы и то, что уже в списке. Одинаковый продукт объединяется в одну строку с перечнем блюд |
| D16 | **«Приготовил» списывает** ингредиенты (с учётом порций) из запасов, не уходя в минус. Отмена снимает отметку, но остатки не возвращает — их правят в «Запасах» |
| D17 | **Отделы магазина** (`aisle`) — фиксированный список; для продуктов без отдела угадывается по названию (`services/aisles.py`). Место хранения при покупке выбирается по отделу (молочное/мясо/овощи → холодильник, заморозка → морозилка) |
| D18 | **Завершение покупки** заменяет поштучные цены: одна сумма чека → один расход в «Продукты» с перечнем купленного. Неизвестные продукты из списка становятся продуктами справочника |
| D19 | **Срок годности и минимальный остаток** — на строке запасов. «Испортится» = ≤ 3 дней; срок важнее количества при выборе статуса |

## Данные (миграция `0003`)

- `food_pantry_items`: `location` (fridge | freezer | pantry), `expires_on`, `min_quantity`.
- `food_meal_slots.cooked_at`.
- `food_shopping_items`: `category` (отдел), `sources` («Плов, Омлет»).
- Единицы `kg`, `l`, `pack` досеиваются при старте (`ensure_default_units` добавляет недостающие коды).

## API (новое)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/food/today` | Слоты дня с готовностью, «испортится», «заканчивается», счётчик списка |
| POST | `/food/menu/slots/{id}/cook`, `/uncook` | Приготовил (списание) / отменить отметку |
| GET | `/food/dishes/{id}/availability?servings=` | Состав vs запасы построчно |
| POST | `/food/dishes/{id}/cook`, `/to-shopping` | Списать / докупить недостающее |
| GET | `/food/shopping-list` | Текущий список (создаётся при необходимости) |
| POST/PATCH/DELETE | `/food/shopping-list/items[/{id}]` | Добавить (с автопривязкой к продукту и слиянием) / изменить / удалить |
| POST | `/food/shopping-list/from-menu`, `/low-stock` | Досыпать из меню / из заканчивающегося |
| POST | `/food/shopping-list/complete` | Купленное → запасы, сумма чека → Finance, остаток → новый список |
| POST | `/food/pantry` | Добавить по `ingredient_id` **или** `name` (новый продукт создаётся), с местом/сроком/минимумом |
| POST | `/food/pantry/{id}/adjust` | ± к количеству (не ниже нуля) |

Старые эндпоинты (`/food/shopping-lists/*`, `generate`, `finalize`, `apply-to-pantry`, `shopping-shortfall`) удалены вместе со складами — новый UI их не использовал.

## Склады (миграция `0004`)

Две квартиры — два склада. Логика как у 1С, но маленькая: остатки по складам, перемещение — документ, все изменения пишутся в журнал.

| ID | Решение |
|----|---------|
| D20 | **Остатки по складу**: строка запасов = (склад, продукт). У дома есть основной склад; при миграции он называется «Дом», и на него переезжают все прежние остатки |
| D21 | **Текущий склад выбирается на устройстве** (`localStorage`) и передаётся как `?warehouse_id=`. Без параметра используется основной. Готовность блюд, «Приготовил», «Заканчивается», «Из меню» и покупка работают с текущим складом. Список покупок общий на дом |
| D22 | **Перемещение — документ** с номером по дому и строками. Проводится целиком или не проводится: если хоть одного продукта не хватает, ничего не меняется («недостаточно на складе»). Единицы конвертируются (кг↔г, л↔мл) |
| D23 | **Отмена проведения** возвращает всё на склад-отправитель. Если на складе-получателе продукт уже съеден или перемещён дальше, отмена запрещена |
| D24 | **Журнал движений** (`food_stock_movements`): приход, покупка, готовка, корректировка, перемещение (расход/приход/отмена), списание. Пишется на каждое изменение количества. Прежние остатки записаны как «Начальные остатки», поэтому сумма движений равна остатку |
| D25 | **Удаление склада**: основной удалить нельзя, склад с остатками тоже нельзя (сначала переместить). Склад с историей архивируется, пустой без истории удаляется |

| Метод | Путь | Назначение |
|---|---|---|
| GET/POST | `/food/warehouses` | Склады со счётчиками «в наличии» / «требуют внимания»; создать |
| PATCH/DELETE | `/food/warehouses/{id}` | Переименовать, значок, сделать основным / удалить (или архивировать) |
| GET/POST | `/food/transfers` | Журнал перемещений / провести новое |
| POST | `/food/transfers/{id}/cancel` | Отменить проведение |
| GET | `/food/pantry?warehouse_id=<id\|all>` | Остатки склада или всех складов (поиск «есть на других складах») |
| GET | `/food/pantry/{id}/movements` | История строки запасов |

Экраны: переключатель склада под заголовком (Сегодня, Меню, Запасы, Рецепты, завершение покупки), шторка «Склады» (выбор, создание, переименование, перемещение, журнал), `/food/transfers/new` и `/food/transfers`. В карточке продукта в «Запасах» есть «Переместить» и «История».
