# Пользовательские сценарии

Каждый сценарий: **триггер → шаги → результат → исключения**.

---

## A. Еженедельное планирование (основной)

**Кто:** планировщик, воскресенье или понедельник.  
**Триггер:** начало недели / пустое меню.

| Шаг | Действие |
|-----|----------|
| 1 | Открыть **Меню**, неделя «текущая» |
| 2 | Для каждого дня назначить ужин (и при желании завтрак/обед) |
| 3 | Выбрать блюдо из каталога или ввести текст («доставка») |
| 4 | Открыть **Список** → «Сгенерировать из меню» за эту неделю (при повторе — выбор: новый список / обновить черновик) |
| 5 | Просмотреть позиции (соль/масло с флагом «всегда дома» не попадут), добавить вручную |
| 6 | В магазине отмечать купленное |
| 7 | По желанию: «Завершить список» + цены → Finance |

**Результат:** согласованная неделя + актуальный список покупок.

**Исключения:**

- Блюдо без ингредиентов → в списке не появится; in-app подсказка «добавьте состав в каталоге».
- Меню изменили после генерации → кнопка «Обновить список» с предупреждением.

---

## B. «Что сегодня на ужин?»

**Триггер:** вечер того же дня.

| Шаг | Действие |
|-----|----------|
| 1 | **Меню** или **Гид** → сегодня |
| 2 | Тап по слоту → карточка блюда, рецепт |
| 3 | При готовке — опционально отметить «приготовили» (фаза 3) |

**Результат:** не ищем рецепт в мессенджере.

---

## C. Быстро добавить новое блюдо

**Триггер:** в каталоге нет нужного.

| Шаг | Действие |
|-----|----------|
| 1 | **Каталог** → «Новое блюдо» |
| 2 | Название + категория + текст рецепта (минимум) |
| 3 | Сохранить → сразу назначить в меню из модалки |

**Результат:** блюдо в базе и в слоте.

**Расширение:** на шаге 2 добавить 2–3 ингредиента для будущих списков.

---

## D. Покупки без полного меню

**Триггер:** срочный поход в магазин.

| Шаг | Действие |
|-----|----------|
| 1 | **Список** → новый пустой или последний активный |
| 2 | Добавить позиции вручную |
| 3 | Отметить купленное |

**Результат:** список не привязан к меню; меню можно заполнить позже.

---

## E. Учёт «что дома»

**Триггер:** после закупки или раз в неделю.

| Шаг | Действие |
|-----|----------|
| 1 | **Склад** → обновить остатки |
| 2 | **Список** → сгенерировать с учётом склада |

**Результат:** в списке только дефицит.

**Исключение:** единицы не сходятся (кг vs г) → позиция всё равно в списке целиком + badge «проверьте единицы» (фаза 2).

---

## F. Повтор прошлой недели

**Триггер:** «готовим как обычно».

| Шаг | Действие |
|-----|----------|
| 1 | **Меню** → «Повторить прошлую неделю» |
| 2 | Подтвердить перезапись |
| 3 | Точечно заменить 1–2 дня |

**Результат:** меню за &lt; 1 мин.

*(Шаблоны — см. домен 2.3, фаза 2.)*

---

## G. Telegram: напоминание на завтра

**Триггер:** cron вечером (бэкенд).

| Шаг | Действие |
|-----|----------|
| 1 | Бот присылает: дата + слоты + названия блюд |
| 2 | Тап «Открыть Monty» → **Гид** или **Меню** на завтра |

**Результат:** оба видят план без захода в приложение днём.

**Исключение:** меню пустое → «Завтра ничего не запланировано» + ссылка заполнить.

---

## H. Закрытие списка и учёт в Finance

**Триггер:** покупки сделаны.

| Шаг | Действие |
|-----|----------|
| 1 | Ввести фактические цены по позициям (или одну сумму) |
| 2 | «Завершить список» |
| 3 | Опционально: «Создать трату в Finance» → категория «Продукты» |

**Результат:** расход в Finance без двойного ввода.

## I. Два человека, два телефона

**Сценарий:** один заполняет меню, второй в магазине.

| Поведение | MVP | Позже |
|-----------|-----|-------|
| Видимость изменений | refresh / повторный вход | polling / push |
| Конфликт правок | last-write-wins | опционально «кто редактировал» |

Отдельный сценарий «пригласить партнёра» не нужен — один дом по умолчанию.

## J. AI: черновик меню (фаза 3)

| Шаг | Действие |
|-----|----------|
| 1 | «Предложить меню» → ограничения (время, не повторять X) |
| 2 | Просмотр черновика недели |
| 3 | Принять целиком / принять по дням / отклонить |

**Результат:** слоты создаются только после подтверждения.
