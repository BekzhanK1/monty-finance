## D1. Стартовый экран Food

**Решение:** **Меню** (`/food/menu`), если при первом заходе в каталоге уже есть сид (≥3 блюда). Иначе редирект на **Каталог** с онбордингом «создайте 3 блюда».

---

## D2. Порции в MVP?

**Решение:** **B** — поле `servings` в слоте меню; генератор списка умножает ингредиенты на `slot.servings / dish.servings_default`.

---

## D3. Перегенерация списка покупок

**Решение:** **C** — диалог при повторной генерации:

- «Создать новый список» (по умолчанию) — предыдущий активный → `done` или архив;
- «Обновить текущий черновик» — только если статус `draft`, с предупреждением о перезаписи позиций из меню.

---

## D4. Удаление блюда, используемого в меню

**Решение:** **B** — soft-delete (`is_archived`). Архивные блюда не в выборе для новых слотов; в прошлых слотах название и рецепт остаются.

---

## D5. «Всегда в кладовой» (соль, масло, специи)

**Решение:** **A** — флаг `is_pantry_default` на **Ingredient**; такие продукты не попадают в список при генерации. В строке состава блюда `is_optional` может явно вернуть продукт в список.

---

## D6. Конвертация единиц при суммировании

**Решение:** **A** на MVP — суммируем только одинаковые `(ingredient_id, unit_id)`. Разные единицы одного продукта → отдельные строки + badge «проверьте единицы» (фаза 2). **B/C** — позже.

---

## D7. Валюта и цены в Food

**Решение:** **A** — всегда одна валюта из настроек Finance; на позиции списка поле `actual_price` (decimal), без `amount_minor` / per-item currency.

---

## D8. Маппинг auth → household

**Решение:** **B** — `household_id` из сессии / профиля пользователя (тот же контекст, что Finance). Убрать константу `MVP_HOUSEHOLD_ID` при реализации.

---

## D9. Идемпотентность Telegram-напоминания

**Решение:** **A** — не более одного сообщения «меню на завтра» в сутки на дом (Asia/Almaty). Повтор при смене меню — не автоматически; опционально кнопка «Обновить напоминание» позже.

---

## D10. Сид данных для новых пользователей

**Решение:** **Да** — при первом bootstrap дома: **5 типовых блюд** (название + категория, без ингредиентов) + in-app подсказка «добавьте состав для списка покупок».

Примеры для сида (уточнить при реализации): омлет, паста, курица с гарниром, суп, салат.

---

## D11. Единица в составе блюда = default продукта

**Решение:** при выборе ингредиента в редакторе блюда поле **«Единица»** автоматически = `ingredient.default_unit_id` (молоко → мл, если так заведено в справочнике).

- Смена продукта в строке → единица **перезаписывается** на default нового продукта.
- Ручная смена единицы **допускается** (редкие рецепты), с подсказкой: «Обычно для этого продукта: мл».
- Backend при `PUT /dishes/{id}/ingredients` **не меняет** правило: любая валидная `unit_id` принимается; валидация «рекомендуемой» единицы — только UI.

---

## D12. Статус готовности блюда по складу

**Решение:** три состояния на уровне **блюда** (для `servings_default` порций, без привязки к слоту меню):

| Статус | UI | Условие (все строки состава с `ingredient_id`, кроме `is_pantry_default` без `is_optional`) |
|--------|-----|-------------------------------------------------------------------------------------------|
| `ready` | 🟢 зелёная галочка | На складе в **той же** `(ingredient_id, unit_id)` достаточно: `pantry.qty >= line.qty` |
| `partial` | 🟡 жёлтый | Есть хотя бы одна строка с достаточным остатком **или** остаток в **другой** единице (как [D6]) |
| `missing` | 🔴 красный | Нет состава **или** ни по одной нужной строке нет достаточного остатка в той же единице |

Строки с `is_pantry_default` и без `is_optional` **не участвуют** в расчёте (как в генераторе [D5]).

Пустой состав → `missing` (или отдельный серый «без состава» — на усмотрение UI).

---

## D13. Пополнение кладовой после покупки

**Решение:**

- При отметке строки **«куплено»** (`checked=true`) и наличии `ingredient_id` — показать действие **«+ на склад»** (или чекбокс «добавить на склад», default **вкл**).
- На склад идёт **фактическое** `quantity` + `unit_id` из строки списка (после правки пользователем), не расчётное из меню.
- Логика склада — как `POST /food/pantry` upsert: та же единица → **сложить**; другая единица → ошибка с текстом как сейчас.
- Повторное «+ на склад» для той же строки **не дублирует** (флаг `pantry_applied_at` на item).
- Массовое действие: **«Отправить купленное на склад»** по всем отмеченным и ещё не отправленным строкам с `ingredient_id`.
